# 學習路線：從 MCP 入門走向 WSI 服務整合

目標：理解 MCP client/server，把既有 WSI（Whole Slide Image，全玻片影像）agent 的功能提供給其他程式使用，再逐步練習多服務協作。

一次增加一個可觀察的概念；已理解的內容不反覆做細碎預測題。以使用者的操作與解釋確認理解，不以建立檔案代替學習成果。

## 目前進度

- 已完成：本機 stdio server/client、列工具、呼叫工具、新增資料並說明資料與工具的差別。
- 已討論：SDK 登記工具與產生描述；host 提供工具定義給模型。
- 使用者已貼回 Codex `/mcp` 的 `mcp_lab: connected (1 tool)`，確認 host 連線與工具發現；真實模型工具呼叫仍待確認。
- [Codex 操作](04-use-in-codex.md)可隨時完成；下一個服務整合主線實驗改為本機 HTTP。
- 原有[第一課](01-mcp-basics.md)、[第二課](02-first-tool.md)保留作參考。完整 JSON-RPC 格式、resource、prompt 在用到時再補。

## 1. 從 stdio 換成 HTTP（下一個實驗）

問題：server 不再由 client 啟動，而是自己先跑著，client 怎麼找到它？

實驗：沿用術語工具與已鎖定的官方 SDK 2.3.0，讓 server 只在 `127.0.0.1` 提供 Streamable HTTP。一個終端機啟動 server，另一個用 Python client 連到本機 MCP 網址。

完成條件：工具與參數不變；client 結束後 server 繼續運行；停止 server 後新查詢失敗。能說明「啟動一個程序」與「連到已運行服務」的差別。此階段不公開部署。

## 2. 做一個假的 WSI 服務

問題：其他程式需要給什麼輸入，才能使用 WSI 的功能？

實驗：先做 `get_slide_info(slide_id)`，接受範例影像 ID，回傳明確標記為 demo 的假資料，不讀真實病患影像、不宣稱執行模型分析。

完成條件：定義清楚的輸入、正常輸出與找不到資料時的行為；普通 Python 腳本能經由 MCP 呼叫。

## 3. 接到既有 WSI 系統

問題：現有 agent 從哪裡啟動？Python 函式、命令列，還是已有 HTTP API？

實驗：取得現有入口與範例輸出後，選擇一項功能，在 MCP 工具內呼叫。已有 API 就沿用；沒有 API 也可以呼叫現有 Python 函式或受控子程序，不必為 MCP 強加一層 HTTP API。

完成條件：相同授權範例透過原入口與 MCP 入口得到一致結果。未知的程式架構、影像格式、耗時與環境，在取得資料前不預設。

## 4. 處理耗時工作（依實測需要）

問題：分析若超過一般請求等待時間，或多人同時提交，怎麼處理？

實驗：先用假耗時工作練習提交取得 `job_id`，再查排隊、執行、成功／失敗狀態，最後取結果；必要時加入取消、併發限制與安全重試。

完成條件：client 暫時離開後仍能查自己的工作；重試不會無意間重複啟動昂貴分析。這是應用程式的工作管理，不假設 MCP 自動提供排程或 GPU 管理。

## 5. 組合兩個服務，先固定流程再加入模型

問題：如何取得 A 的輸出，再把需要的部分交給 B？

實驗：普通 Python 腳本先呼叫兩個本機假服務，例如 WSI 範例資訊與另一項範例資料服務，依固定流程組合結果；再視需要讓模型選下一個工具。

完成條件：沒有 LLM 時流程也能跑；能追蹤各次呼叫的輸入、輸出與錯誤。加入模型後，能區分模型選擇與程式路由。

先練習一個統整程式呼叫多服務。個別 agent 需要呼叫別人時，也可內含 MCP client；不先假設所有 agent 都要彼此自由互叫。

## 6. 部署到團隊伺服器／內網

問題：另一台有權限的電腦，如何使用 WSI 服務？

實驗：確認團隊伺服器的權限、網路與既有入口；處理執行環境、常駐程序、網路路由、必要的 TLS 與存取驗證，再從另一台電腦測試。

完成條件：重啟後可恢復；有權限者能呼叫，沒有權限者不能取得資料或結果；日誌足以定位問題。是否開放公網，依使用需求決定，開埠不等於完成部署。

## 7. 接入使用者入口（依合作方案）

問題：LINE Bot 等入口收到需求後，如何交給統整程式，再取得結果？

實驗：先用本機模擬訊息驗證整條流程；合作方確認後才接真實入口，沿用它所需的外部協議。內部服務可留在受控網路。

完成條件：能追蹤一筆需求從入口、各服務到最終回覆；知道哪段使用 MCP、哪段使用一般 API，以及由誰決定工作流程。

## 每個實驗的節奏

1. 用專案的一個問題說明概念。
2. 做最小實驗，觀察實際呼叫與結果。
3. 由使用者說明關鍵觀察；已掌握的細節直接往下。
4. 記錄問題與下一步，檢查指定檔案後 commit、push。
