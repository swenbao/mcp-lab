# 學習路線

目標：你能說明 MCP 解決什麼問題，並親手執行一組能溝通的 MCP client 與 server。每課約 30–60 分鐘，依實際理解程度調整，不設定截止日期。

目前進度調整（2026-10-20）：使用者已完成最小查詢與資料修改，能解釋工具／資料差別，也已掌握工具描述的用途。接下來先做第 4 階段的[Codex 實驗](04-use-in-codex.md)，完整訊息格式留到需要時回看第 3 階段；已理解的概念不反覆做細碎預測題。

## 0. 專案與備份

問題：程式、學習筆記與 GitHub 備份放在哪裡？

產出：Git repository、教學計畫、公開 GitHub repo 與第一次 push。

完成條件：可以在 GitHub 看見 README 與學習筆記，知道下一課要做什麼。

## 1. 先畫出角色

問題：MCP 是協議，server 是程式，那 AI 在哪裡？

活動：閱讀 [第一課](01-mcp-basics.md)，用「查詢術語」畫出 host → client → server → 資料的路徑。

完成條件：能用自己的話區分 host、client、server；知道 server 可以在本機執行。

## 2. 第一個工具與連線

問題：client 怎麼知道 server 有哪些功能？又怎麼呼叫？

活動：依[第二課](02-first-tool.md)執行最小範例、修改一筆資料。環境已確認 Python 與官方 SDK 版本、建立虛擬環境並鎖定依賴；範例提供 `lookup_term` 與最小 Python client，透過 stdio 列出工具並查詢 `tool`。

觀察：工具名稱、description、inputSchema、輸入參數及回傳內容；分清「直接呼叫 Python 函式」與「經過 MCP 跨程序呼叫」。

完成條件：從乾淨啟動開始，一個指令能完成連線、列出工具、呼叫並顯示結果，不依賴模型 API。

## 3. 讀懂一次交換

問題：SDK 幫我們包裝了什麼？輸入不合法會怎樣？

活動：依實際版本觀察能力與版本發現、`tools/list`、`tools/call`；比較正常查詢、未知術語與缺少必要參數。

完成條件：能指出 request 的 method、id、params，以及 response 對應的結果或錯誤。了解版本差異後，再閱讀完整 JSON-RPC 訊息。

## 4. 接進 AI 應用程式

問題：工具成功執行和 AI 自己回答有什麼差別？

活動：選擇你已使用且支援 MCP 的 host，按照該 host 的官方文件接入 server。比較開啟工具與未使用工具的回答，查核實際工具呼叫紀錄。

完成條件：host 可以發現並呼叫 `lookup_term`；使用者能解釋模型選擇、host 路由與 server 執行各自的工作。

## 5. 認識另外兩種能力

問題：一份參考資料、可執行的工具與可重用的提示模板，為何要分開？

活動：沿用同一個 demo，新增術語表 resource，再新增學習測驗 prompt；透過測試 client 驗證各自操作。選擇 host 前先確認它支援哪些能力。

完成條件：能針對一個需求，說明選用 tool、resource 或 prompt 的理由。

## 6. 選修：HTTP 與自己的小專案

問題：把同一組能力放到 HTTP 後，什麼改變了？

活動：使用已鎖定 SDK 支援的 Streamable HTTP，先只綁定 localhost，再用 client 驗證相同工具。比較程序生命週期、位址與錯誤。對外部署與驗證授權留待後續需要時學習。

完成條件：本機 HTTP client/server 可以溝通，並且能提出一個自己的小專案，例如公開文件查詢或單位換算，寫出一個 tool 的輸入、輸出與驗收條件。

## 每課固定節奏

1. 回顧上次的一個問題。
2. 解釋這次的一個新概念。
3. 一起完成最小實驗，預測並觀察結果。
4. 由你說明發生了什麼，記錄仍不清楚的部分。
5. 更新學習紀錄，commit、push，確認雲端已有該次成果。
